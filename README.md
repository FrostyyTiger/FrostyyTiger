# Marcel Bierbauer-Szigeti

Co-founder and CTO of Navigo Intelligence, a small self-funded software company near Zurich. Our construction-site product has had its first customer live in production since September 2026, and our tax-return workflow for Swiss fiduciary firms is at demo stage.

Two decisions say most about how I build: tenant isolation in Postgres row-level security rather than application code, and outward sends that wait for a person to confirm them. How it's built, and why: **[navigo-engineering](https://github.com/FrostyyTiger/navigo-engineering)**.

Coding agents write the code. I decide what gets built, write the specs and acceptance criteria, and I'm accountable for what ships.

## Projects

- **foundry** is my own tool for building software with agent loops: one loop turns meeting recordings into draft requirements a person approves, another builds approved requirements into merged code, bound by the product's tests and CI. It works on Navigo's products; its first real run took one requirement of our construction product from plan to merge in about 100 minutes. The code is private and its public page is coming. <!-- link runfoundry.dev once live -->
- [life-agent](https://github.com/FrostyyTiger/life-agent) is a morning-brief agent built to run under an OS account that can't edit the agent's own code.
- [Kubik](https://github.com/FrostyyTiger/Kubik) is a co-op voxel game I'm building with a friend, in Godot 4 with the meshing in C++.
- [adcs-testbed](https://github.com/FrostyyTiger/adcs-testbed) is my design for a desktop spacecraft model that stays pointed while its arm moves.
